# Wiring the real sign recognizer

The app currently runs `FakeSignRecognizer`, which discards every camera frame.
`MediaPipeSignRecognizer` implements the same `SignRecognizer` interface, so the swap is one line.

## 1. Files (already in this patch at their repo paths)

```
android/app/src/main/java/edu/postech/signbridge/ml/SignPreprocessor.kt
android/app/src/main/java/edu/postech/signbridge/ml/ParityTest.kt
android/app/src/main/java/edu/postech/signbridge/vision/MediaPipeSignRecognizer.kt
```

## 2. Assets → `android/app/src/main/assets/`

```

```

It skips itself unless `parity_fixture.json` is in assets (generated by `make_fixture.py` in notebook 03).

## 5. What to look at in Logcat

| Tag | Meaning |
|---|---|
| `SignBridgeRecognizer` | `ready: 20 words, input 1x32x204` on start; any per-frame exception |
| `SignBridgePerf` | every 60 frames: `fps`, `mediapipe ms/frame`, `model ms/run`, current top word |
| `SignBridgeParity` | `PASS` / `FAIL` / `SKIP` |

The `SignBridgePerf` line is the on-device latency evidence for the presentation and report.

## Tuning knobs (top of MediaPipeSignRecognizer)

- `STRIDE` (3) — classify every Nth frame.
- `BODY_EVERY` (5) — pose + face every Nth frame.
- `SWAP_HANDS` (false) — flip if on-device accuracy is far below the notebook's 80.6%.
- The ViewModel's `MINIMUM_SIGN_CONFIDENCE` (0.65) and 450 ms hold still decide when a word is spoken.

## Note

`minSdk = 36` limits the app to Android 16 devices. MediaPipe Tasks needs 24, CameraX 23, Vosk 21.
If nothing in the app needs API 36, lowering it matches the "any Android phone" claim.

Not compiled in the authoring environment (no Android SDK there). The preprocessing arithmetic was
verified against the Python notebook on 600 random clips; the MediaPipe/CameraX glue was not run.
